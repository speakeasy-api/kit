**Scope-overlap law (normalized to sub-wave).** Two units dispatched in the same **sub-wave** MUST have disjoint write whitelists at path level. No non-integrator unit may list any shared-file path. Violation → unit rejected before review.

**Shared-file set (integrator-owned), three groups:**

1. **Program files** — `Cargo.toml`, `Cargo.lock`, `requirements/registry.yaml`, `requirements/evidence.yaml`, `requirements/tombstones.yaml`, `requirements/merge-lock.yaml`, `docs/compatibility/manifest.yaml`, `.github/workflows/`, `ci/lanes/`.

**Scaffold handoff (three exceptions, each stated once and exercised once).** (i) Scaffold unit `1.02` creates `src/lib.rs`, `src/main.rs`, the 13 module roots and the four empty harness `main.rs` files in sub-wave `W1.L1`, before any integrator is dispatched (`1.INT-A` is `W1.L2`, `1.INT` starts at `W1.L3`); from `W1.L3` those 19 files are integrator-owned and `1.02` never edits them again. (ii) `1.13` creates the 12 `ci/lanes/*.yaml` files at `W1.L5`; from Wave 2 onward `ci/lanes/` is integrator-owned and the lane count is frozen at 12 — `1.INT` therefore does **not** list `ci/lanes/`. (iii) `Cargo.toml` and `Cargo.lock` are generated and owned by `1.INT-A` for the whole of Wave 1 and pass to the merge authority thereafter.

**Global merge serialization — program-wide, not per wave.** Per-wave integrator exclusivity is **insufficient and is not claimed here**: `W3`‖`W4` and `W4.5`‖`W5`..`W11` dispatch concurrently by design (§6.1), so `3.INT`/`4.INT`, and `12.INT` against each of `5.INT`..`11.INT`, would otherwise write `Cargo.toml`, the registry aggregate, the harness entrypoints and the module roots at the same instant. Therefore:

- There is exactly **one merge authority for the whole program**. Every `*.INT` unit is a *turn* in one serialized queue, not a concurrent role. Two integrator units may never overlap in time, in any wave pair.
- Lock artifact: `requirements/merge-lock.yaml` — one file, keys `holder` (`null` or a literal `<wave>.INT` id), `sub_wave`, `sequence` (monotonic integer), `acquired_at`, `queue` (FIFO list of waiting `<wave>.INT` ids). Created by `1.INT-A` at `W1.L2` with `holder: null`, `sequence: 0`.
- Authority = compare-and-swap on that file. An integrator may begin a merge pass only by an atomic transition of `holder` from `null` to its own id with `sequence` incremented by exactly 1. A CAS observing a non-null `holder` appends the unit to `queue` and blocks. Release sets `holder: null` and pops the queue head.
- Machine-checked invariant: at every instant `holder` names at most one unit, and the `sequence` values recorded on merge records in `requirements/evidence.yaml` form a gap-free strictly increasing integer sequence — `0` concurrent merge passes, `0` gaps, `0` reuse.
- Concurrent **product** workers remain fully concurrent and disjoint; only `*.INT` merge passes serialize. A worker never blocks on the lock because a worker never writes a shared file.
- The merge authority is also the evidence-number allocator (see `evidence_id` above).

Companion law (dependency levelling): a unit's `SW` level MUST be strictly greater than the `SW` level of every dependency inside the same wave. A dependency at the same `SW` level is a dispatch error, not a scheduling hint.

## 11. Review, Security and Replan Loops

### 11.1 Per-unit loop (mandatory order)

```text
dispatch -> implement -> self-verify (run the unit's exact acceptance commands)
   -> simplify pass          (remove accidental complexity; no behavior change)
   -> code review to zero    (reviewer returns findings until zero remain)
   -> security review        (REQUIRED if the unit's write scope touches auth,
                              file, network, secret, executor, storage,
                              protocol, or multi-tenant surfaces)
   -> gate check             (evidence recorded into requirements/evidence.yaml
                              via the wave integrator)
   -> ACCEPTED | REJECTED | BLOCKED
```

`REJECTED` returns to implement with the findings attached. `BLOCKED` emits a new `BLK-*`/`EXT-*` row with owner + action + verification and does **not** consume the gate.
