## Scope

- Configured MCP sampling responders validate bounded text/audio/image input,
  treat peer content as untrusted data, remove tools and ambient context, bind
  the configured model, and dispatch a detached durable model session only
  after current attempt, fence, claim, revision, grant, budget, cancellation,
  secret, and callback authority checks.
- Sampling request and optional response approvals are versioned durable Kit
  callbacks. Detached model intent precedes provider dispatch; validated outcome
  and exact actual usage/cost settlement precede response preparation. Exact
  replay does not redispatch or recharge, and uncertain delivery is not success.
- Per-turn maximum output tokens, temperature, and stop sequences are carried
  through AgentKit. Anthropic, Cerebras, Ollama, OpenAI, and OpenRouter project
  requested controls exactly or reject unsupported controls before intent or
  reservation. Ollama's OpenAI-compatible path enforces `max_tokens`.
- OpenAI-compatible and Anthropic usage normalization retains separately
  reported cache, reasoning, output, and provider-cost categories without
  counting them twice. Provider pricing used for sampling is complete, versioned,
  model-bound, and either positive-budget or explicitly local-free Ollama.
- Form elicitation accepts only configured public-data schemas and exact safe
  fields. Requests, schemas, messages, property counts/names, response bytes,
  content, deadlines, and secret scans are bounded; accepted content is stored
  as a service-owned artifact rather than peer-supplied authority.
- Roots response is limited to one source root. Stdio derives it from the
  executor profile's source mount. HTTP requires an explicit shared-filesystem
  mapping whose local source equals the pinned project root. Only a clean
  absolute server path is rendered as a bounded `file:` URI; absent proof
  advertises no root.
- The capability broker remains the policy and dispatch authority. AgentKit
  receives a sanitized callback identity, generation, cancellation view, and
  one-use delivery permit, never a peer handle or independent policy decision.
- Durable callback states are `requested`, `awaiting_resolution`, `resolved`,
  `response_prepared`, `delivered`, `delivery_unknown`, `expired`, and
  `interrupted`. Callback identity binds run, attempt, fence, claim generation,
  server, connection generation, operation sequence, request, schema, workspace
  revision, secret policy, and deadlines.
- Authenticated HTTP and CLI expose pending/get/resolve operations through the
  same service command/query path. Resolution rechecks principal, project,
  grant, kind, mode, version, challenge generation, schema digest, attempt,
  fence, claim, workspace revision, idempotency digest, and cancellation before
  commit.
- Crash recovery reconciles callback artifact publication and exact callback
  CAS/idempotency state. Dispatched detached model work is not blindly replayed;
  actual overage remains charged. Run and transcript erasure scrub matching
  callback projection, event, idempotency, reservation, and artifact data while
  preserving unrelated tenants and required backup inventory.
