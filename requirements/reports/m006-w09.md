## Scope

- `tool_learning.v1` is a closed, bounded six-class record format for final
  provider opportunities, searches, inspections, calls, fixed errors, and
  terminal outcomes. It stores no prompt, query, description, schema,
  arguments, output, URL, error text, reasoning, or secret. Linkable values are
  project-scoped keyed pointers.
- Learning records append to the run-correlated SQLite stream with project-keyed,
  domain-tagged pointers, durable operation ordinals, bounded operation
  admission, and reserved terminal capacity. Canonical call identity includes
  the keyed run pointer, turn, operation sequence, provider call, route, and
  argument digest, so changed arguments cannot collide while approval/auth
  continuations retain the original call. Call records precede generic parsing and bound-schema
  validation; terminal error pairs append atomically. Learning links only
  reference committed kernel identities. Auth, approval, URL continuation, and
  replay do not create a second terminal learning outcome.
- Every persisted record's project-keyed event MAC and stable event identity
  cover the complete canonical record except the MAC itself. Status, count,
  class, and pointer substitutions therefore fail recovery validation. Reads
  and exports additionally verify queried run/project, event row identity,
  correlation, stream, outbox frame, and raw run metadata.
- Final provider opportunities count only the exact tool specs offered to the
  provider. Portable generic mode offers four host specs and omits its
  authorized-but-hidden bindings from candidates. Early generic and
  deferred failures use the same run/turn/operation/call identity and retain
  resolved capability, schema, binding, source, kind, sequence, and field
  pointers.
- The primary SQLite store maintains a bounded learning outbox. Export encrypts
  each frame before the `Exporter` boundary and acknowledges the exact outbox
  records only after sink commit. The local encrypted sink keeps bounded SQLite
  frame deduplication; plaintext learning export is rejected.
- Outbox admission enforces global and project row/byte ceilings with terminal
  reservation over pending bytes/rows only; only batches carrying an outcome
  can consume the terminal reserve. Reads, acknowledgements, and exported-row retention are project
  scoped; run-bound stats snapshots prune only after encrypted export. Export
  failure updates required/best-effort health but cannot change a completed run.
- The production executor no longer registers every authorized MCP descriptor
  as an eager direct tool. Native tools retain their configured eager policy;
  MCP uses the authorization-filtered `DiscoverySession` search, inspect, and
  bind path and the `RegistrationPlan` generic invoke projection. Runtime
  bindings derive only from the current catalog and grants; learning telemetry
  is never runtime authority, and an empty authorized MCP catalog is valid.
- MCP transport, broker auth, credential, egress, URL elicitation, response,
  cancellation, and unknown-outcome failures retain fixed distinct classes and
  codes rather than collapsing to `BrokerAuth`.
- MCP redirect handling builds one encoded-secret matcher per response hop.
  Every inbound response scanner starts from fresh residual state, while chunks
  within that response retain continuity independently of outbound fields.
- Durable operational outcomes update a bounded SQLite catalog-stats overlay in
  the same transaction as their linked learning records. Encrypted run-boundary
  snapshots rederive every count from authenticated source events before export;
  abandoned rows are project/globally bounded and snapshots prune transactionally.
- The bounded deterministic analyzer consumes raw learning records plus
  preregistered experiment arms and downstream grade records. It reports the
  four RFC signal classes only for eligible linked events when both arms and
  verified grade receipts exist. Description findings require a declared
  description-only intervention with frozen other factors; prospective sequence
  steps contain only capability/schema pointers, surface, and ordinal. Analysis
  binds observed call pointers and requires an exact ordered sequence with at
  least two distinct capabilities, noninferior grades, and attributable cost or
  latency improvement. Harmful requires a verified
  security, rollback, or defect receipt.
- Final-report freeze includes every roster trial, including terminal-error
  receipts and their authenticated terminal evidence. It loads authenticated
  learning records through each measured receipt watermark, preregistered paired
  arms, projected candidates and surfaces, observed sequence pointers, and harness grades/cost from the
  production SQLite authorities. The analyzer result and all linked input
  digests are inside the canonical authority-signed report bytes before freeze;
  there is no separate analysis table. Missing authority, records, candidates,
  arms, grades, or linkage remain explicit unavailable results.
- Learning export has independent sticky health/readiness. Ordinary telemetry
  flush cannot clear a learning store/auth/encryption/export/ack/stats failure;
  best-effort learning never changes the run result and required readiness stays
  failed until an explicit successful learning operation.
