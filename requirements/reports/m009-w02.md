## Invariants

- Exactly four states with the legal graph `Candidate -> Validated | Rejected`,
  `Validated -> Promoted | Rejected`; `Rejected` and `Promoted` are terminal
  (`src/agent/compaction/states.rs:173-181`).
- Every versioned record binds checkpoint ID, run ID, attempt ownership (attempt, principal, fence),
  driver lease ID, operation sequence, expected durable-head sequence, base and candidate transcript
  digests, candidate artifact content digest and opaque reference (kept as distinct
  `ArtifactDigest`/`ArtifactReference` types from `src/store/artifacts/mod.rs:16,58`), and mutation
  point (`src/agent/compaction/states.rs:119-138`).
- Exact replay is idempotent (`TransitionApplied::Replayed`); the same logical transition with
  conflicting identity or data returns a typed error; illegal and conflicting transitions leave the
  record byte-identical (`src/agent/compaction/states.rs:262-313`).
- Deserialization of a `CheckpointStateRecord` is validating: untrusted wire payloads are replayed
  through the same `apply` path, so a payload whose state, version, or applied transitions are
  mutually inconsistent — a forged state or version, duplicate or out-of-order applied transition,
  misplaced rejection reason, non-monotonic sequence, or unknown field — is rejected (adversarial
  coverage in `tests/conformance/checkpoint_states.rs:forged_wire_records_cannot_bypass_transition_invariants`).
  This is structural validation only, not authentication: a self-consistent unauthenticated payload
  still decodes, and head movement is separately gated by `DurablePromotedHead::advance` (run
  binding plus sequence/digest CAS). No claim of wire authenticity or store integrity (W06/W07) is made.
  Unknown fields are rejected at every contract-controlled wire level: the record envelope, the
  nested binding, the binding's `owner` (via a module-local strict wire around the shared
  `AttemptOwnership` type, which itself derives a lenient `Deserialize` outside this scope), each
  applied transition entry, and `CheckpointTransition` all deny unknown fields.
- Driver lease IDs and rejection reasons accepted from untrusted input are bounded
  (128 / 1024 bytes, `src/agent/compaction/states.rs:22-23`); both accept only visible ASCII
  (reasons additionally allow ordinary spaces), so control, bidirectional-override, and zero-width
  characters are rejected. The bounded debug text embedded in
  `UnsupportedMutationPoint` errors is likewise sanitized: characters outside visible ASCII plus
  spaces are replaced before bounding, so a hostile upstream `Debug` impl cannot place control,
  bidirectional-override, or zero-width characters in operator-visible diagnostics.
- A `Candidate` record carries digests only and cannot mutate live context; `DurablePromotedHead` is
  bound to a `RunId` at construction, and a promoted record from any other run is rejected with a
  typed error (`HeadRunMismatch`) before any sequence, digest, replay, or mutation consideration, so
  a foreign or forked run cannot advance the head even with a matching expected sequence and base
  digest; only a `Promoted` record from the head's own run whose expected head sequence and base
  transcript digest both match the current head advances it; fields are private with `advance` as the
  sole mutation path; replay is acknowledged only for the exact binding of the promotion the head
  itself recorded (a head constructed without promotion history never acknowledges one, and a
  conflicting record claiming the current sequence returns a typed error); the head derives no serde
  traits, so it cannot be forged from wire input; `Rejected` retains the prior head.
- The head is bound to the run, not permanently to an attempt: the durable head outlives any single
  driver attempt within a run, and the source contract assigns attempt/fencing authorization to the
  promotion operation (W06 atomic promotion), not to head construction. Per-promotion attempt
  authorization therefore remains deferred W06 truth; binding the head to one attempt here would
  wrongly reject later legitimate attempts of the same run.
- `Validated` is Kit-authoritative validation eligibility, not agentkit transcript-pair validation
  (`src/agent/compaction/states.rs:171-172`); its authoritative inputs arrive in W05.
- An `Unknown` hook outcome maps to `AwaitReconciliation` for the same checkpoint identity and never
  to `Rejected` or `Promoted`; `Committed` records a durable candidate without a state change;
  `NotCommitted` maps to a bounded rejection (`src/agent/compaction/states.rs:445-469`).
- Safe checkpoints map only `MutationPoint::AfterToolResult -> SafeBoundary::AfterToolOutcome` and
  `MutationPoint::AfterTurnEnded -> SafeBoundary::TurnEnd`; any future variant of the upstream
  `#[non_exhaustive]` enum fails closed (`src/agent/compaction/states.rs:97-117`), with the upstream
  `#[non_exhaustive]` attribute and variant count pinned by a brace-depth-aware source scan.
- Records carry no transcript content, reasoning parts, or other hidden model output; wire field sets
  are pinned exactly by test.
