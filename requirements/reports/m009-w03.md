## Contract

### Entry points

`evict(&EvictionRequest) -> Result<EvictionOutcome, EvictionError>` and
`accept_mutation_point(MutationPoint) -> Result<CheckpointMutationPoint, EvictionError>`
(`src/agent/compaction/evict.rs:397-406`).

`EvictionRequest` borrows the transcript and the fact list; the request carries a W02
`CheckpointMutationPoint`, so only `AfterToolResult` and `AfterTurnEnded` are representable, and
`accept_mutation_point` maps upstream `MutationPoint` through W02's fail-closed
`CheckpointMutationPoint::from_agentkit` (`src/agent/compaction/states.rs:100-108`).

`EvictionOutcome` is `Fits(EvictionPlan)` or `Insufficient(EvictionPlan)`
(`src/agent/compaction/evict.rs:247-254`). `Insufficient` means every eligible unit was consumed and
the protected remainder still exceeds the target; no protected fact is ever discarded to reach it.

### Explicit bounds

All eight bounds are caller-supplied in `EvictionLimits` (`src/agent/compaction/evict.rs:56-65`).
Limit validity, item count, fact count, and fact IDs are checked before transcript inspection
(`src/agent/compaction/evict.rs:406-415`):

| Bound | Meaning | Checked before |
| --- | --- | --- |
| `max_items` | transcript item count | traversal, clone, serialization |
| `max_visited_parts` | recursively visited parts, nested reasoning paths included | further traversal |
| `max_part_depth` | nesting depth, additionally capped by `MAX_SUPPORTED_PART_DEPTH` (8) | further recursion |
| `max_json_depth` | nonreasoning JSON value nesting, additionally capped by `MAX_SUPPORTED_JSON_DEPTH` (64) | clone or serde traversal |
| `max_tool_output_bytes` | nonreasoning payload preflight and exact serialized bytes of each reasoning-free `ToolOutput` | token estimate or digest |
| `max_canonical_bytes` | aggregate nonreasoning source material and exact reasoning-free canonical `Vec<CanonicalItem>` bytes | token estimate or digest |
| `max_token_estimate` | `estimate_tokens` over exact reasoning-free canonical bytes | selection or digest |
| `max_facts` | eviction fact count | fact validation or transcript traversal |

Zero structural/byte/token limits, part depth above 8, or JSON depth above 64 are
`EvictionError::InvalidLimits`; a zero fact limit is valid for an empty fact list. Recursive part
inspection and rebuilding use checked depth increments. A `Part::Reasoning` consumes one visited-part
slot and one bounded source-relative path only; its summary, data, redacted flag, and metadata are not
inspected, accounted, cloned, or serialized (`src/agent/compaction/evict.rs:606-659`). Every
nonreasoning source surface (IDs, strings, metadata keys and values, tool names and output, URIs,
inline data, file fields, custom fields, and retained usage strings) is counted before it is cloned
into a candidate.
Iterative JSON preflight, visited parts, file lists, output budgets, and serialization writers use
checked arithmetic (`src/agent/compaction/evict.rs:548-883,1044-1120,1260-1379`).

The first candidate/payload clone always builds the reasoning-free estimation projection and clears
only AgentKit's typed `Usage.tokens.reasoning_tokens` field
(`src/agent/compaction/evict.rs:419-434,1044-1072`). A bounded second traversal then validates the exact
serialized bytes of every remaining `ToolOutput`, including nested outputs, followed by the exact
canonical bytes; both checks complete before any token estimate or digest
(`src/agent/compaction/evict.rs:1122-1190`). No full source transcript or unsanitized `ToolOutput` is
serialized. Per-removal exact re-estimation remains bounded by `max_facts`,
`max_visited_parts`, `max_part_depth`, `max_tool_output_bytes`, and `max_canonical_bytes`.
Redundant nested reasoning entries use strict ancestor-prefix `BTreeSet` probes bounded by
`max_part_depth`, rather than scanning the full removal set for every reasoning path
(`src/agent/compaction/evict.rs:215-224,446-492`).

### Categories

Deterministic order is the declaration order of `EvictionCategory`
(`src/agent/compaction/evict.rs:167-188`): stale raw log, superseded map, duplicate read, reasoning
part, successful command noise. The algorithm executes that order directly. Pair-atomic selection and
candidate rebuilding use stable oldest source position/part path/typed opaque `ToolCallId` order.
After each category executes, only that category's selected manifest entries are canonicalized by
global source position/part path/`ToolCallId` before append; there is no cross-category post-sort
(`src/agent/compaction/evict.rs:446-492,943-1026`). Overlapping pairs can therefore have nonadjacent
manifest entries while remaining one atomic selection unit. Manifest entries carry only a
domain-separated tool-call-ID digest, never the raw provider ID
(`src/agent/compaction/evict.rs:190-198,1214-1219`). Grouped duplicate reads and maps retain and move
their first resolved `EvictionUnit`; they are not resolved or cloned a second time
(`src/agent/compaction/evict.rs:943-1026`).

- **Stale raw log** — requires an explicit `FactClassification::StaleRawLog` fact for a succeeded
  operation. No prose, tool-name or model authority is consulted.
- **Superseded map** — requires an explicit `map_key` and `generation`. Within one key the newest
  generation is retained, ties broken by the latest completion position; the rest are eligible.
- **Duplicate read** — requires an explicit `equivalence_key`. Within one key the newest completed
  (succeeded) occurrence is retained; older completed occurrences are eligible.
- **Reasoning part** — the only category with no fact. Every `Part::Reasoning` is stripped
  unconditionally, including parts nested in `ToolOutput::Parts`. Required removal metadata retains
  only the exact category and source-relative path; no reasoning summary, data, metadata, or other
  payload byte reaches limit accounting, the final candidate, removal metadata, diagnostics, or any
  digest. AgentKit's explicit `Usage.tokens.reasoning_tokens` is also cleared; every nonreasoning usage
  field remains byte-for-byte equal. No metadata-key, prose, tool-name, or model heuristic is used.
  Reasoning enters the physical removal set at its declared fourth category. A separate estimation
  view overlays every reasoning path for earlier target decisions. The candidate is materialized from
  the physical set at the reasoning category; a path already covered by an earlier pair removal has no
  redundant manifest entry. Redacted `Debug` may show `ReasoningPart` and its location, but not its
  payload (`src/agent/compaction/evict.rs:419-500,630-659,1044-1072`;
  `tests/conformance/evict_determinism.rs:393-427,458-549,1180-1286`).
- **Successful command noise** — requires an explicit `FactClassification::SuccessfulCommandNoise`
  fact. A `Failed`, `Cancelled` or `OutcomeUnknown` operation is rejected with
  `EvictionError::NonSuccessfulCommandNoise`; in every other category a non-succeeded outcome makes
  the material ineligible, so it is retained. A succeeded fact naming an AgentKit error result fails
  closed with `EvictionError::FactOutcomeMismatch`
  (`src/agent/compaction/evict.rs:918-935,943-1009`). Facts
  reuse the durable `EffectStatus` type (`src/agent/driver/restart.rs:262-267`) rather than defining a
  second outcome authority.

An otherwise valid, eligible fact naming a tool call absent from this transcript has no effect, which
makes re-applying the same fact set to a candidate a fixed point.

### Pairing

Top-level `ToolCallId` values are validated as 1..=256 UTF-8 bytes, must be unique, and must pair with
exactly one top-level `ToolResult` at a strictly later position. Unicode provider IDs accepted by
AgentKit remain valid. Duplicate, orphaned, out-of-order and in-flight top-level pairs fail closed
before eviction, and the same validation runs again over the candidate
(`src/agent/compaction/evict.rs:416-418,498-499,888-910`). A pair is
the atomic removal unit: the call part and the result part are always removed together, so no orphan
is retained. `ToolOutput::Parts` content is recursively inspected for bounds and reasoning removal but
is not reinterpreted as transcript protocol, matching AgentKit's top-level invariant validator
(`vendor/agentkit/crates/agentkit-loop/src/lib.rs:3532-3573`). Removing the final part retains the
source item envelope, including ID, metadata, nonreasoning usage, finish reason and timestamp
(`src/agent/compaction/evict.rs:1044-1072`).

### Purity and digests

The source transcript is borrowed and never mutated; the candidate is rebuilt from the source and a
source-relative removal set, so no index shifts and the operation is idempotent
(`src/agent/compaction/evict.rs:1044-1120`). No durable event or artifact is touched — this module has
no store dependency.

- Candidate/input digest: domain-separated BLAKE3 (`KIT-COMPACT-EVICT-CANDIDATE\0`) plus the
  algorithm version over canonical `Vec<CanonicalItem>` bytes produced by the existing
  `agentkit_bridge::mapping::from_agentkit_item` (`src/agent/compaction/evict.rs:1180-1212`). The input
  digest identifies the reasoning-free source projection; neither reasoning parts nor typed reasoning
  token usage reaches a digest or threshold. Cost, metadata, input/output/cache token usage, and every
  other nonreasoning usage field are preserved exactly. The regression varies only
  `reasoning_tokens` and proves identical estimates, selection, candidate, input/candidate/eviction
  digests, and outcomes (`tests/conformance/evict_determinism.rs:458-549`).
- Eviction digest: domain-separated BLAKE3 (`KIT-COMPACT-EVICT-MANIFEST\0`) binding the algorithm
  version, the input digest, the candidate digest, the mutation point, the target, and the ordered
  removal manifest through deterministic JSON serialization of `EvictionDigestInput`
  (`src/agent/compaction/evict.rs:1222-1258`).
- `EVICTION_ALGORITHM_VERSION` is exactly `4` and is bound into candidate, tool-call-ID, and eviction
  digest inputs (`src/agent/compaction/evict.rs:45-47,1206-1219,1222-1258`).

Errors are typed and closed (`src/agent/compaction/evict.rs:331-348`). No error carries transcript
content, reasoning bytes, or an unbounded user-controlled string. `EvictionPlan` has a redacted custom
`Debug` implementation that reports digests/counts but never candidate content
(`src/agent/compaction/evict.rs:281-294`).
