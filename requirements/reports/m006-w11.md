## Contract

The daemon owns one shared registry restored from transactional SQLite project snapshots. Public
callers cannot select trust or provide mutation scope: trusted registration is crate-private,
requires the existing nonforgeable daemon token, and is restricted to the build allowlist; public
registration always derives untrusted scope from an authenticated principal and permits protocol
routes only.

Canonical snapshots contain contracts and lifecycle only. They are bounded before every commit by
per-principal/project and global row and canonical-byte quotas. Restore validates scope, canonical
encoding, contracts, digests, duplicate keys, and supersession targets. Runtime trusted attestation
and broker authorization are never serialized; restored trusted entries are inactive until
build-attested registration, and untrusted resolution always requires a fresh opaque broker
authorization.

Every durable registration, resolution, and launch gate first compares the local registry revision
with the singleton SQLite registry revision and reloads all validated scope snapshots on mismatch.
The singleton revision, aggregate entry count, aggregate canonical-byte count, and changed scope
snapshot commit in one immediate transaction, so distinct scopes share one global quota CAS.

Configured production MCP bootstrap registers the contract with an implementation digest equal to
the exact verified executable bytes and binds that digest to the launch receipt. Linux launch copies
those bytes into a private `O_EXCL` file, fsyncs and rehashes them through a read descriptor, unlinks
the file before spawn, and passes only that descriptor to bubblewrap's trusted read-only data bind;
platforms without that safe primitive fail closed. The broker binds route, sandbox profile,
principal, project, workspace revision, config/grant snapshots, delegation, credential, and egress
scopes, and validates them before launch. Every registered invocation checks current registry
lifecycle and then passes through the
existing broker's current fence, lease, catalog binding, schema, implementation, grant and transport
authorization. Native built-ins use the same durable shared registry and re-resolve current lifecycle
at dispatch.
