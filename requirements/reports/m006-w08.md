## Scope

- The MCP HTTP client uses one bounded egress connector for every initial URL
  and manual redirect hop. Exact configuration and broker-derived credential
  authority precede DNS and secret resolution. Resolution is bounded, all
  addresses must be public, every address is pinned into a no-proxy,
  no-retry, no-auto-redirect client, and the actual connected peer must match.
- Redirects are bounded to five hops and exact `Location` bytes. Relative URLs
  are resolved against the current hop. Loops, HTTPS downgrade, ambiguous
  301/302/303 method rewriting, dangerous schemes and ports, userinfo,
  fragments, local names, alternate numeric hosts, mixed/private/special DNS,
  DNS changes, and peer mismatch fail closed.
- Requests are rebuilt on every hop. Authorization, proxy authorization,
  cookies, MCP session identifiers, Last-Event-ID, and origin-sensitive headers
  are not inherited. The exact next-hop opaque credential is resolved only
  after that hop is authorized. Redirect response headers are scanned against
  every active credential before use.
- Configuration supports at most five exact HTTPS redirect origins, each with
  its own opaque credential handle and explicit project/workspace scope. The
  connector retains no unused hop-record serialization; resolver and dialer
  seams remain injectable, while the production dialer retains
  no-proxy/no-retry/no-auto-redirect behavior.
- Resource links, descriptor URIs, structured result links, and other
  server-originated URLs remain typed untrusted data. No browser opener, file
  reader, model-context injection, or automatic URL fetch was added.
- Form and URL elicitation are advertised only when separately configured. URL
  requests accept only exact configured HTTPS origins and bounded message, URL,
  identifier, response, and deadline fields. URLs remain only in authenticated
  callback projections.
- AgentKit's typed `-32042` URL elicitation error is reused. Durable callbacks
  bind the original invocation, idempotency digest, server, operation,
  generation, invocation-request digest, exact terminal-error response digest,
  URL digest, actor/project/workspace, grant digest, attempt, fence, claim,
  revision, retry safety, typed undispatched proof, and deadline. Accept retries
  an idempotent original tool operation exactly once through fresh broker and
  per-hop authorization; non-idempotent, duplicate, changed, stale, restarted,
  expired, or uncertain cases settle `outcome_unknown`. Decline and cancel do
  not retry.
- Callback responses use the existing one-use delivery permit and final
  authority check. The authenticated API and CLI remain the only resolution
  path; URL acceptance requires current network-egress authority.
