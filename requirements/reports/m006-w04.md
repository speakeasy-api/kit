## Mechanical Acceptance

`CatalogEntry` and `CatalogSnapshot` are immutable after construction. Every entry explicitly carries
all seven W04 metadata groups: immutable identity; source plus trust domain; availability; side-effect
plus retry-safety classification; reliability plus attempted, succeeded, failed, cancelled, and
outcome-unknown usage counts; latency statistics; and cost statistics. Entries additionally retain
exact input and output schema source bytes, dialect, documentation, normalized form, and provider
projections; compact summary and search terms; schema and implementation digests; required grants and
authentication scopes; and version.

The catalog represents all six source kinds: native tools, project plugins, MCP servers, ACP client
capabilities, A2A peers, and provider-native tools. All six current native descriptors convert into
entries while preserving identity, input schema, grants, side effects, and retry safety. Conversion
derives the output schema and catalog digests and assigns current native availability. External
protocol, provider, and project adapters are not yet connected, so this local conversion does not
establish the broader production federation promised by `KIT-CAP-801`.

The source-independent collision key is exactly namespace, name, and version. A cross-source collision
returns typed `IdentityCollision`; a same-source duplicate returns typed `DuplicateIdentity`. A source
ID binds one exact source kind and trust domain, with conflicting metadata rejected. Exact-source
replacement builds a complete new snapshot before publication, shares unaffected old `Arc` entries,
and leaves the old snapshot immutable after success or failure.

Schema, entry, and snapshot digests are canonical, versioned, and compositional. They cover exact
schema source, dialect, documentation, normalized bytes, projection target/profile/digest metadata,
all entry metadata, and ordered entry digests. Canonical key ordering makes snapshot digests insertion-
order independent. Reliability, latency, and cost counts, totals, extrema, sample relationships,
currency, and overflow are checked, and every side-effect class must be backed by its required grant.
