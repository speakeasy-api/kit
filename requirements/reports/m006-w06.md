## Registration Selection

A same-process provider contract must explicitly declare deferred-registration support and supply an
opaque support value constructed by validating a `ProjectionProfile`. All four host schemas
(`tools.search`, `tools.inspect`, `tools.bind`, and `tools.invoke`) are projected and validated against
that profile. Deferred mode additionally requires the declaration and support to identify the exact
same projection target and profile digest and every bound capability to have that exact target,
profile digest, and dynamic input-schema digest. Any absent, unsupported, or mismatched contract or
projection selects the deterministic portable generic mode.

The registration surface reuses AgentKit `ToolSpec`. `tools.search`, `tools.inspect`, and `tools.bind`
are always eager. `tools.invoke` is eager exactly once only in portable mode; direct bound definitions
exist only in deferred mode. Eager and deferred definitions are sorted, direct names are provider-safe
and bounded, and deferred metadata binds the exact `BindingId`, schema digest, and profile digest.

## Registry And Invocation

The immutable binding registry accepts one catalog only, is bounded at 4096 entries, accounts at most
64 MiB of catalog payload, rejects duplicate bindings, and commits its full catalog digest and sorted
binding IDs into a registry digest. Plan creation validates every binding against the current discovery
session. Definition access and invocation revalidate the current session and plan generation; stale or
foreign sessions and registry, catalog, schema, or authorization mismatches fail closed.

Direct and generic routes share one bounded JSON normalization path. It rejects duplicate keys and
non-lossless numbers, enforces common depth and node limits, and canonicalizes accepted input. Direct
calls enforce the inner-input maximum on raw bytes before preflight and canonicalization; generic calls
enforce the outer-wrapper maximum before preflight and the same inner maximum on canonical bytes. Both
then validate the pinned binding and pinned schema before calling the synchronous dispatch callback.
Every tested error calls the callback zero times. The callback is a provider-agnostic seam to the
existing M006-W03 broker, not a second effect executor.

Across 120 independently expected observations, direct and generic routes are field-equal for binding
ID, capability identity, schema digest, authorization-snapshot digest, parsed input, and canonical
input bytes. This establishes local kernel composition with the M006-W03 broker path; it is not a
production provider run.

Catalog, grant, policy, schema, and expiry semantics are inherited from M006-W05. Registration does
not weaken full-catalog invalidation or current-session authorization validation.
