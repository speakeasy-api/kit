# Edit staging

`workspace::edit::stage::stage` consumes a live `ValidatedPlan`; the plan is revalidated before its guard and retained descriptor capabilities enter staging. The same mutation guard remains owned by the returned `StagedEdit`, and the workspace revision is revalidated after the source copy. A plan cannot be replayed because staging consumes it by value.

The stage allocation is outside the named workspace, below the managed workspace's descriptor-opened private state root, and its allocation root has mode `0700`. It never uses a predictable global `/tmp` queue. The implementation copies through no-follow directory descriptors with end-to-end entry, byte, name, path, metadata-memory, and deadline bounds. It rejects symlinks, special files, hardlinks, mount crossings, and descriptor identity changes. Reflinks and hardlinks are not used because this layer has no filesystem-specific proof that writes cannot reach the source object. The complete workspace tree is copied so unrelated regular files, directories, bytes, and modes remain present, while requested operations are applied only to the private view.

The staged result owns private directory handles, its allocation identity marker, the mutation guard, accepted capabilities, a descriptor snapshot of the complete final tree, and a nonce-derived binding. It cannot be serialized or forged. No allocation or host path is exposed, and staging is never replaced by a daemon host command implementation. `StagedEdit::read_file` opens below the retained final-tree descriptor and revalidates the accepted digest before returning bytes. Its public summary contains the canonical staged-envelope digest, validated-plan digest, revision, and the exact sorted changed set with before/after content hashes and normalized modes. The staged edit and its lifecycle remain the seam where a staged-view verifier (for example, LSP diagnostics against the staged tree) can plug in before materialization.

Allocation and cleanup are relative to a trusted parent descriptor: atomic `mkdirat` immediately installs an RAII owner for mode `0700` roots, every component is opened no-follow, and the allocation marker and bounded cleanup record are fsynced before the allocation is returned. Each record binds the parent device/inode, allocation device/inode, nonce, marker, exact current name, and idempotent `Original -> Quarantined -> Deleted` state. A new workspace owner replays only checksum-valid durable records and resumes exact-identity quarantine deletion while holding the owner operation lock; it never discovers or removes allocations by glob. Unrecorded matching names remain untouched, while corrupt records and replaced identities fail for manual handling. Same-process manager reuse never runs recovery. `StagedEdit::close` surfaces cleanup failure; Drop journals a failed cleanup rather than silently leaking the workspace.

Syntax requirements are derived for every resulting changed file from extension policy. The sealed production executor advertises only `rust`/`kit-syn-rust-v1`, `json`/`kit-native-json-v1`, and `text`/`kit-native-text-v1`; every other exact language/version pair is unavailable. All three parsers run in a hidden Kit worker subprocess, never on the staging thread. The worker receives only bounded source bytes on stdin, runs with a cleared environment and non-repository working directory, and returns only a tiny typed result. The parent concurrently bounds both capture streams, owns the worker process group, applies a hard pre-exec memory limit, and kills and reaps it at the wall deadline. On macOS, production syntax is advertised only after a sacrificial worker proves that the Darwin address-space and data limits deny an allocation beyond a finite budget; an unenforcing kernel makes syntax typed unavailable before parsing. Rust uses `syn` full-file parsing; JSON uses `serde_json`; text enforces UTF-8, no NUL, and one coherent newline style. Executor input is read back from stage descriptors. Syntax runs against the applied view and again against the fresh final snapshot.

Validated output is copied into a fresh private final descriptor tree. Only after the complete copy, every final file is frozen to `0400` and every directory to `0500`. The kernel mutation fence remains held through exact final comparison, syntax, digesting, and a final clean recheck. Deterministic `state_digest` binds the complete logical final tree, edit plan, staging limits, and exact syntax results. Separate `evidence_digest` is derived under its own domain string. Any rejection discards the allocation without publishing staged bytes into the workspace.
