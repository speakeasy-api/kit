# Edit staging and formatter boundary

`workspace::edit::stage::stage` consumes a live `ValidatedPlan`; the plan is revalidated before its guard and retained descriptor capabilities enter staging. The same mutation guard remains owned by the returned `StagedEdit`, and the workspace revision is revalidated after the source copy and after formatter completion. A plan cannot be replayed because staging consumes it by value.

The stage allocation is outside the named workspace, below the managed workspace's descriptor-opened private state root, and its allocation root has mode `0700`. It never uses a predictable global `/tmp` queue. The implementation copies through no-follow directory descriptors with end-to-end entry, byte, name, path, metadata-memory, and deadline bounds. It rejects symlinks, special files, hardlinks, mount crossings, and descriptor identity changes. Reflinks and hardlinks are not used because this layer has no filesystem-specific proof that writes cannot reach the source object. The complete workspace tree is copied so unrelated regular files, directories, bytes, and modes remain present, while requested operations are applied only to the private view.

The staged result owns private directory handles, its allocation identity marker, the mutation guard, accepted capabilities, a descriptor snapshot of the complete final tree, and a nonce-derived binding. It cannot be serialized or forged. No allocation or host path is exposed. `StagedEdit::read_file` opens below the retained final-tree descriptor and revalidates the accepted digest before returning bytes. Its public summary contains the canonical staged-envelope digest, validated-plan digest, revision, exact sorted changed set, before/after content hashes and normalized modes, bounded formatter capture, overlay identity, and process evidence.

Allocation and cleanup are relative to a trusted parent descriptor: atomic `mkdirat` immediately installs an RAII owner for mode `0700` roots, every component is opened no-follow, and the allocation marker and bounded cleanup record are fsynced before the allocation is returned. Each record binds the parent device/inode, allocation device/inode, nonce, marker, exact current name, and idempotent `Original -> Quarantined -> Deleted` state. A new workspace owner replays only checksum-valid durable records and resumes exact-identity quarantine deletion while holding the owner operation lock; it never discovers or removes allocations by glob. Unrecorded matching names remain untouched, while corrupt records and replaced identities fail for manual handling. Same-process manager reuse never runs recovery. `StagedEdit::close` surfaces cleanup failure; Drop journals a failed cleanup rather than silently leaking the workspace.

Syntax requirements are derived for every resulting changed file from extension policy. The sealed production executor advertises only `rust`/`kit-syn-rust-v1`, `json`/`kit-native-json-v1`, and `text`/`kit-native-text-v1`; every other exact language/version pair is unavailable. All three parsers run in a hidden Kit worker subprocess, never on the staging thread. The worker receives only bounded source bytes on stdin, runs with a cleared environment and non-repository working directory, and returns only a tiny typed result. The parent concurrently bounds both capture streams, owns the worker process group, applies a hard pre-exec memory limit, and kills and reaps it at the wall deadline. On macOS, production syntax is advertised only after a sacrificial worker proves that the Darwin address-space and data limits deny an allocation beyond a finite budget; an unenforcing kernel makes syntax typed unavailable before parsing. Rust uses `syn` full-file parsing; JSON uses `serde_json`; text enforces UTF-8, no NUL, and one coherent newline style. Executor input is read back from stage descriptors. Syntax runs before formatting and again against the fresh final snapshot.

Formatters run only through the sealed executor-owned `FormatterExecutor`; there is no public runner trait, completion constructor, host-path request, or daemon host command implementation. Production construction uses the M003 registered container/helper path with persist-before-release ownership, bounded streamed output and wall time, and authoritative zero-survivor inspection. Its virtual root is read-only, the descriptor-pinned stage source is a separate read-only mount, the formatter sees only a writable copy-on-write overlay, build and temp are writable, and credentials and egress are absent. Neither the live workspace nor the accepted stage/final root is writable or mounted into the formatter. Descriptor image, command, arguments, requested binary digest, and requested effective-config digest are carried in the `kit-container-v1` plan before its digest is computed. The helper's monitor channel remains protocol-only. Separate formatter child stdout/stderr reports carry sanitized bounded previews, full lengths and digests, an explicit redact-before-report assertion, and a nonce/plan/invocation-bound output attestation. `ExecutionReport`, `FormatterCompletion`, and staged formatter evidence retain those fields, so nonzero formatter diagnostics are not replaced by empty monitor captures. The helper evidence also returns `formatter_binary_digest`, `formatter_config_digest`, and `formatter_artifact_digest` beside the resolved image digest. All three measurement fields must be present and valid together. The executor accepts only helper-measured image/artifact, executable, and effective-config digests matching the requested constraints; missing or mismatched measurements are rejected. A missing external helper remains typed unavailable. Requested values are never substituted as evidence.

Before invoking a formatter, staging copies the planned tree into distinct read-only source and writable overlay descriptors. The versioned `FormatterWriteScope` binds only known base digests/modes, the declared changed files, and allowed change kinds; it never invents unknown result digests. After all Kit-controlled pre-execution writes, the executor establishes the clean kernel fence immediately before releasing the formatter. Formatter-writable directories are added only after quiescence and recursive revocation; no formatter-window event on the immutable stage is drained, and no event after revocation is cleared through snapshot and finalization. The executor constructs a versioned `ExecutorAttestedDiff` from the sealed artifacts with exact base/result kinds, digests, and modes. Staging independently compares the revoked tree and final copy to that attestation. It rejects setid/sticky bits, ownership changes, directory or file ACLs/xattrs, symlinks, hardlinks, special files, directory or regular-file mount changes, metadata aliases, and races. The metadata rejection policy is versioned into tree identity.

Validated output is copied into a fresh private final descriptor tree after the writable layer is revoked; the formatter never receives a handle to this tree. Only after the complete copy, every final file is frozen to `0400` and every directory to `0500`. The kernel mutation fence remains held through exact final comparison, syntax, digesting, and a final clean recheck. Deterministic `state_digest` binds the complete logical final tree, edit plan, formatter/image/artifact/config constraints and exact syntax/formatter results. Separate `evidence_digest` binds invocation, runtime plan, process boundary, timing, capture, and quiescence evidence. Any rejection discards the allocation without publishing staged bytes into the workspace.

Production formatter execution is explicitly unavailable on macOS until a sealed formatter sandbox backend exists. Formatter-free staging remains supported there; debug-only formatter fixtures do not claim production isolation.
