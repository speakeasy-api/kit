# Grammar-constrained edit output

`m004-w09.grammar-edit` version 1 is an explicit run/experiment configuration. It defaults off in the built-in effective config and has no environment-variable override. User and project layers cannot select it. Enabling it does not add grants or alter model authorization, reservations, accounting, events, streaming limits, or verification policy.

When enabled in an explicit debug/development run, Kit requests constraints only when the sealed concrete provider session reports compatible strict structured-output support and accepts the bounded canonical schema. Anthropic `output_config.format` is the initial supported projection. OpenAI, OpenRouter, Ollama, and unknown cells either fail or use ordinary output according to `unsupported_provider`; callers cannot supply a support matrix. An ordinary request can never be reported as constrained.

Before dispatch, Kit opens one managed workspace, captures its revision and content digest, and uses that same `GrammarEditContext` through projection, intent persistence, terminal classification, and execution. Both constrained and ordinary fallback requests receive the explicit structured-edit instruction and schema contract; the constrained schema binds `expected_revision` with `const`. A revision change during the model call is a typed rejection, and execution never reopens the workspace to derive a replacement revision.

Kit supplies AgentKit's normalized per-turn schema/name/version/strict/digest contract. The concrete AgentKit provider adapter owns projection into provider-native request fields. AgentKit validates returned JSON against the requested schema before producing honored evidence, and Kit requires matching schema and request-correlation evidence rather than trusting a structured part alone. Kit does not duplicate provider wire protocols.

Constrained output is the same structured JSON accepted by `ModelEditFormat::StructuredJson`: version, expected revision, and the four Edit IR input operations without canonical IDs or order fields. Constrained structured output and ordinary JSON, whole-file JSON, or unified diff all call the existing `normalize_with_trace`, which rebuilds with `EditIr::new`. The adapter cannot construct a `ValidatedPlan` or mutate a workspace. The resulting IR continues through `validate_traced`, `stage_traced`, `verify_traced`, and `materialize_traced`.

The deterministic path IDs are `edit.normalize.v1`, `edit.ir.new.v1`, `edit.validate.v1`, `edit.stage.v1`, `edit.verify.v1`, and `edit.recovery.v1`. Output mode is intentionally absent from these IDs so semantically equal constrained and ordinary outputs have exactly equal traces from normalization onward.

Schema, instruction, and projected request bytes are included in the pre-intent budget reservation. Schema and streamed output bytes are bounded before parsing. Only `Completed` can be accepted; cancellation, provider error, other/blocked/max-token/tool-call finishes, a provider that ignores a constraint request, malformed data, and oversized data are typed failures and cannot reach validation. Intent and outcome evidence records the experiment identity/digest, workspace revision/digest, request correlation, selected mode, provider/model capability version, exact schema contract, fallback, and honored result; verification binds that immutable outcome rather than recomputing it.

Anthropic support comes only from exact, adapter-versioned model cells with a sealed dialect and keyword set. Development has an explicit fixture cell; unknown models fail or use configured ordinary fallback. Release has no enabled production cells. Release materialization rejects activation even though the default-off shape remains parseable, and no release adapter can activate the path until `KIT-EVAL-834` is accepted.
