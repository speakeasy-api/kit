# Edit materialization and recovery

`StagedEdit::materialize` is the only publication path for a staged edit. It consumes the immutable stage while retaining the exact `WorkspaceMutationGuard`, mutation nonce, accepted path capabilities, base revision, plan digest, complete staged tree, and final tree digest. The guard computes the one expected successor revision before recovery preparation and rejects a different guard, base revision, final content digest, or successor at commit.

Recovery state lives below the managed revision state root, outside the mutable workspace. Before any directory, image, or artifact allocation, a descriptor-relative global ledger durably records the nonce, transaction name, and workspace and metadata-store identities. The transaction directory then receives a synced marker. Before the first workspace effect, a compact manifest binds those identities, the exact base epoch/revision/digest, the exact successor epoch/revision/digest, authority, artifact envelope, ordered operations, actions, cleanup remainder, and the exact v2 verification receipt. The receipt binds verification schema/plan/stage-binding/result/evidence digests and every opaque stdout/stderr artifact reference and length. Every state change is bounded before a complete temporary JSON file is written, synced, atomically renamed, and followed by a directory sync; JSON is never appended. Recovery handles ledger-only, directory-only, temporary, manifest, and final-ledger states without treating an interrupted manifest write as permanent corruption.

All workspace access walks from the retained root descriptor with `O_NOFOLLOW`. Files must remain single-link regular files. Publication uses private `O_EXCL` files in the destination directory, syncs bytes and modes, verifies the resulting identity, and uses no-clobber rename. Existing sources are verified immediately before being moved aside. Symlink components, hardlinks, special files, mount crossings, aliases, stale revisions, and unexpected destination objects are rejected by staging, retained capability revalidation, descriptor checks, and the canonical final workspace scan. Empty directories and unrelated files are not rewritten; file bytes, binary content, CRLF style, missing final newlines, and executable modes come from the materialized stage rather than the model representation.

The durable states are `staged`, `prepared`, `materialized`, `committed`, `rolled_back`, and cleanup. Recovery rolls back only when metadata is the exact base tuple and rolls forward only when it is the exact successor tuple. Both directions preserve the byte-identical verification receipt and validate all referenced stream artifacts before touching the workspace. A later or unrelated root fails without mutation. Cleanup atomically moves each exact identity to a private deterministic trash name, records the reduced remainder, and then unlinks it. The final ledger state is synced before manifest removal, so every unlink, directory removal, manifest removal, and ledger cleanup can resume idempotently.

The revision boundary is the synced canonical workspace metadata record and guard record. All file and parent-directory effects are synced before that boundary. Recovery then appends the committed transition and performs identity-checked cleanup. Cleanup progress is durable and retried on the next admission; a live call that commits but cannot finish cleanup returns `RecoveryError::CommittedCleanup` with the committed result instead of reporting an unqualified failure.

The diff is generated from the captured before images and final staged images, not from edit IR text. Its deterministic envelope binds transaction, successor revision, authenticated typed principal/project authority, plan, and stage. Images are streamed into a bounded, synced transaction file and then streamed into the artifact store under the same deadline. The durable reference precedes publication and records class, media type, authority, retention, byte count, digest, and local image identity. Minimum retention is enforced independently of caller policy. Only the explicitly bounded preview is model-facing, including its truncation marker.

Managed readers acquire the workspace operation lock and therefore observe only a recovered old or new revision. Materialization updates individual paths sequentially because the implementation does not atomically exchange the workspace root. Raw external filesystem readers that bypass the manager can observe an intermediate tree; no atomic visibility guarantee is made for them.

`tests/fault/edit_recovery.rs` injects every state transition and every applicable per-file action point. Startup must produce either the complete old tree before revision commit or the complete staged tree after it, with no destination temporary left in the workspace.

Run the process-death recovery evidence with `cargo test --locked --test fault edit_recovery::real_process_death_matrix_recovers_exact_tree -- --exact`. The harness requires the injected child to terminate with exactly `Some(86)` for `_exit(86)` cases or signal `9` for `SIGKILL` cases; a generic failure status is not accepted as crash evidence.
