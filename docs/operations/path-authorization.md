# Workspace path authorization

Workspace path authorization is implemented on Linux and macOS. Windows and other targets expose the same API but return `PathAuthError::Unavailable`; Kit does not claim equivalent path safety on those targets.

## Authority

The caller first acquires `ManagedWorkspace::mutation_guard` for the expected revision. The mutation guard owns the same stable-read state used by `ManagedWorkspace::stable_read_guard_before`, serializes transaction-scoped mutation work, and reconciles the workspace after taking the guard. `PathAuthorizer::new` is then bound to that exact guard, expected revision, epoch, and an unforgeable random per-guard nonce. Capability lifetimes are invariant in the guard borrow, and consumption checks the nonce again. Every capability issue and consumption reconciles again; a changed workspace returns typed staleness rather than issuing or using stale authority.

The authorization root is the managed workspace's already-open root inode. Descriptor traversal follows that object even if its original pathname is renamed. The retained root pathname is used only to detect named-root replacement; this layer never creates, removes, renames, truncates, or otherwise mutates a name. On macOS, descriptor mount identity binds the filesystem ID together with the retained root inode. A named mount/root replacement ambiguity returns `PathAuthError::Unavailable`; this is sufficient for exact-handle opening and reading and is not a claim of publication safety.

Each requested path must be a non-empty UTF-8 root-relative `RootRelativePath`. Absolute paths, parent/current components, empty components, Windows aliases, non-NFC spellings, `.git`, `.kit`, and Kit metadata names are rejected. `FilesystemIdentityPolicy::Portable` is the default. `CaseSensitive` fails unavailable unless the root's case and normalization behavior can be proven with a safe probe; this non-mutating layer does not currently perform such a probe.

On Linux and macOS, every untrusted component is streamed through bounded alias enumeration, inspected with `fstatat(AT_SYMLINK_NOFOLLOW)`, and opened only through one private audited helper. The helper enforces `O_NOFOLLOW | O_CLOEXEC` and uses Linux `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS)` when available, with a one-component no-follow `openat` fallback on kernels without `openat2`. Each parent is watched before its child name is enumerated or opened; each opened component is watched and matched back to its name before traversal continues. Issuance requires a clean event fence, expected-revision reconciliation, and a second clean fence check, so a transient swap restored before issuance is still rejected. Directory and file descriptors must remain on the root device and mount. Unsupported nonlocal filesystems, symlinks, hardlinked regular files, special files, and mount crossings fail closed.

Authorization returns one of six owned descriptor capability types: `ExistingRead`, `ReplaceSource`, `DeleteSource`, `CreateParent`, `MoveSource`, or `MoveDestination`. Existing/source capabilities retain the exact opened file handle. Create and move-destination capabilities retain the opened parent directory plus a validated absent leaf identity. Absence is authorization input only, not a promise that the name remains absent or can be published later. Immutable bindings record root identity, revision, epoch, normalized path identity, object or parent identity, type, mode, and authority. Callers cannot construct capabilities.

## Consumption

Only `ExistingRead` has a public consumption operation in this layer. It seeks and streams the retained handle through a fixed buffer under `EditLimits` content and memory bounds; it never reopens the authorized name. Substituting any pathname therefore cannot redirect the read. Alias enumeration is also streaming and enforces entry-count, aggregate name-byte, and transient-memory bounds. The elapsed-time limit is a cooperative deadline checked between filesystem syscalls, including streaming reads; it does not interrupt a blocked syscall or claim a hard wall-clock bound. There is no unbounded directory `Vec` or `read_to_end`.

Replace, delete, create, and move capabilities expose bindings but no live publication operation. A later copy-on-write staging/materialization layer owns those effects and must consume them under the same transaction boundary.
